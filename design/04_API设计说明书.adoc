== 1 设计约定

=== 1.1 基础约定

[cols="1,3"]
|===
| 项 | 约定

| Base URL | `/api/v1`（`server.servlet.context-path`）。下文路径均省略该前缀，例如 `POST /auth/login` 的完整地址为 `/api/v1/auth/login`

| 数据格式 | 响应统一 `application/json; charset=utf-8`

| 字段命名 | 小驼峰（camelCase），与后端 Java 字段一致：`userId`、`roleCode`、`pageSize`

| 参数形式 | 除特别标注外，参数均为 *query / 表单参数*（`@RequestParam`）；标注"请求体"的为 JSON（`@RequestBody`）

| ID 类型 | 主键为 `Long` 自增整数；登录响应中的 `userId` 为字符串

| 时间格式 | ISO 8601 本地时间，不带时区：`2026-10-24T16:13:19`（时区为 Asia/Shanghai）。请求中的时间参数（如 `expireTime`）使用同一格式

| 枚举取值 | 大写编码：账号状态 `NORMAL / DISABLED / SEALED / LOCKED`；角色类型 `FUNC / DATA`；操作取值 `NONE / VIEW / ALL / VIEW_EDIT …`（12 种，见《数据库设计说明书》3.8）

| 分页 | 请求参数 `page`（从 1 开始，默认 1）、`size`（默认 20）；响应为 `PageResult`（1.3 节）
|===

=== 1.2 认证与鉴权

* 除 `POST /auth/login` 外，所有接口必须携带请求头 `Authorization: Bearer {accessToken}`。
* 每个请求由拦截器依次执行：
. *认证*：校验令牌签名、签发方、有效期，并确认令牌未被吊销。失败返回 401（2001～2004）。
. *鉴权*：若当前接口（Controller 映射模板 + HTTP 方法，如 `PUT /users/{userId}/status`）已在 `iam_function_point` 中登记为 `ADMIN` 系统的功能点，则要求当前用户经角色拥有该功能点，否则返回 403（2007）。未登记的接口只要求登录。
* 初始化数据 `seed.sql` 已把第 3 章全部已实现的管理端接口登记为功能点，并授予超级管理员角色 `SUPER_ADMIN`；默认管理员 `admin / Admin@123`。

=== 1.3 统一响应包

所有接口返回 `Result`：

[source,json]
----
{
  "code": 0,
  "message": "success",
  "data": {},
  "timestamp": "2026-10-24T16:13:19.170295"
}
----

[cols="1,1,3"]
|===
| 字段 | 类型 | 说明

| code | int | 业务码，0 表示成功，其余见 1.4 节

| message | string | 人类可读信息

| data | object / array | 业务数据；为空时整个字段省略（只对 `Result` 本层生效，`data` 内部对象的空字段仍输出为 `null`）

| timestamp | string | 服务端时间
|===

分页接口的 `data` 为 `PageResult`：

[source,json]
----
{ "total": 1, "page": 1, "pageSize": 20, "list": [] }
----

=== 1.4 错误码

HTTP 状态码随业务码变化，见下表（与 `common/enums/ErrorCode.java` 一致）。"RBAC0 使用"列标出当前已实现接口会返回的错误码。

[cols="1,2,1,3,1"]
|===
| 业务码 | 名称 | HTTP | 说明 | RBAC0 使用

| 0 | SUCCESS | 200 | 成功 | 是

| 1001 | PARAM_INVALID | 400 | 参数校验失败：缺少必填参数、类型错误、枚举取值非法、业务参数不合法 | 是

| 1002 | PARAM_MISSING | 400 | 必填参数缺失（登录账号或密码为空） | 是

| 1003 | PARAM_FORMAT_ERROR | 400 | 格式错误 | 否

| 1004 | IDEMPOTENCY_CONFLICT | 409 | 幂等键冲突 | 否

| 1005 | RESOURCE_NOT_FOUND | 404 | 资源不存在（用户、角色、模块、功能点、绑定、未知路径） | 是

| 2001 | UNAUTHENTICATED | 401 | 未登录 / 未携带令牌 / 账号或密码错误 | 是

| 2002 | TOKEN_INVALID | 401 | 令牌无效（签名或格式错误、令牌库中不存在） | 是

| 2003 | TOKEN_EXPIRED | 401 | 令牌过期 | 是

| 2004 | TOKEN_REVOKED | 401 | 令牌已吊销（已登出、账号被停用或封存） | 是

| 2005 | ACCOUNT_SEALED | 403 | 账号已封存（离职） | 是

| 2006 | ACCOUNT_DISABLED | 403 | 当前登录账号停用或锁定（只在登录时返回） | 是

| 2007 | NO_FUNCTION_PERM | 403 | 无功能权限 | 是

| 2008 | OUT_OF_DATA_SCOPE | 403 | 越数据范围 | RBAC3

| 2009～2011 | SIGNATURE_INVALID / REPLAY_DETECTED / APP_DISABLED | 401 / 401 / 403 | 对外签名、防重放、接入停用 | 扩展

| 3001 | ROLE_MUTEX_CONFLICT | 409 | 角色互斥冲突 | RBAC3

| 3002 | ROLE_INHERIT_CYCLE | 409 | 角色继承成环 | RBAC1

| 3003 | ORG_MOVE_INVALID | 409 | 组织节点移动非法 | RBAC3

| 3004 | USER_ALREADY_SEALED | 409 | 用户已封存，不能再变更状态 | 是

| 3005 | GRANT_DUPLICATE | 409 | 重复授权 | 是

| 3006～3008 | APPROVAL_REQUIRED / DATA_SCOPE_EXPIRED / LOCK_ACQUIRE_FAILED | 409 | 审批流、临时授权过期、分布式锁 | 扩展 / RBAC3

| 3009 | RESOURCE_DUPLICATE | 409 | 资源已存在（账号、角色编码、系统编码、API 已登记） | 是

| 3010 | TARGET_USER_ABNORMAL | 409 | 操作对象（被授权的用户）非正常状态，不能授权 | 是

| 4001 | RATE_LIMITED | 429 | 触发限流 | 扩展

| 5000 | INTERNAL_ERROR | 500 | 服务器内部错误 | 是

| 5001～5002 | SERVICE_UNAVAILABLE / DEGRADED | 503 / 200 | 依赖不可用 / 决策降级 | 扩展
|===

2005、2006 只表示*当前登录账号*被封存或停用，前端收到后会强制登出；操作对象（如被授权的用户）状态异常一律用 3010，不会影响操作人的会话。

错误响应示例（未登记权限的用户调用 `GET /users`）：

[source,json]
----
{ "code": 2007, "message": "无功能权限: 查询用户列表", "timestamp": "2026-10-24T16:13:19.496944" }
----

== 3 管理端接口（已实现）

=== 3.1 认证（M01）

==== POST /auth/login

请求体（JSON）：

[cols="1,1,1,3"]
|===
| 字段 | 类型 | 必填 | 说明

| username | string | 是 | 账号（`user_no`）
| password | string | 是 | 密码
| captchaId / captchaCode | string | 否 | 验证码（预留，当前不校验）
| clientIp | string | 否 | 客户端 IP，写入令牌记录
|===

响应 `data`：

[cols="1,1,3"]
|===
| 字段 | 类型 | 说明

| accessToken | string | 访问令牌（JWT，有效期 2 小时）
| tokenType | string | 固定 `Bearer`
| expiresIn | long | 有效期（秒），默认 7200
| userId | string | 用户 ID
| displayName | string | 姓名（解密后）
| accountStatus | string | 账号状态
| refreshToken | string | 刷新令牌，当前固定为 `null`（规划接口，见 6.1）
|===

错误：1002（账号或密码为空）、2001（账号或密码错误，不区分账号是否存在）、2005（已封存）、2006（停用 / 锁定）。

==== POST /auth/logout

请求头携带要吊销的令牌。成功后该令牌立即失效（再次使用返回 2004）。令牌不存在时视为已登出，同样返回成功。

==== GET /auth/validate

请求头携带令牌，`data` 为 `true` / `false`。令牌无效时由拦截器直接返回 401，不会到达本接口。

=== 3.2 用户账号（M02）

用户接口返回 `UserView`（不含密码哈希与密文）：

[cols="1,1,3"]
|===
| 字段 | 类型 | 说明

| id | long | 用户 ID
| userNo | string | 账号
| realName | string | 姓名（解密后）
| phoneMasked | string | 脱敏电话，如 `138****5678`；未填电话时为 `null`
| orgId | long | 所属组织 ID
| post | string | 岗位
| accountStatus | string | 账号状态
| leaveTime / lastLoginAt | string | 离职时间 / 最近登录时间
| isDeleted | int | 0 / 1
| createdAt / updatedAt | string | 创建 / 修改时间
|===

[cols="1,2,3,2"]
|===
| 接口 | 参数 | 说明 | 错误

| `POST /users` | `userNo`、`realName`、`orgId`；可选 `password`、`phone`、`post` | 创建账号，返回 `UserView`。未传 `password` 时使用初始密码（配置项 `iam.default-password`） | 3009 账号已存在；1001 缺参数

| `GET /users` | 可选 `page`、`size`、`orgId`、`accountStatus` | 分页查询未删除的账号，返回 `PageResult<UserView>` | —

| `GET /users/{userId}` | — | 账号详情 | 1005

| `PUT /users/{userId}/status` | `targetStatus`；可选 `reason` | 变更状态。非 `NORMAL` 时吊销该用户全部令牌；`SEALED` 时同时回收全部角色并记录离职时间 | 1001 状态取值非法；1005；3004 已封存
|===

[cols="1,2,3,2"]
|===

== 4 开放鉴权接口（已实现）

供业务系统和前端调用，同样需要 `Authorization` 头。判定规则见《详细设计说明书》6.6 节。

[cols="1,2,3"]

| 接口 | 参数 | 响应 `data`

| `GET /open/permissions` | `userId`、`systemCode` | 功能点 ID 数组，如 `[10001, 10003, 20001]`。前端据此控制菜单与按钮（FR-36、FR-39）

== 6 规划接口（扩展，尚未实现）

V1.0 中设计、当前代码尚未实现的能力，保留设计要点作为后续实现依据：

=== 6.1 认证扩展

* `POST /auth/refresh`：刷新令牌换取新的访问令牌（FR-34 续期）。
* `GET /auth/profile`：当前用户信息、角色列表与权限版本号。
* SSO：`GET /sso/authorize`（携带 `systemCode`、`redirectUri`、`state`，302 回跳一次性授权码）、`POST /sso/token`（授权码换令牌）（FR-31）。
* 对外应用认证：业务系统以 `X-App-Key`、`X-Timestamp`、`X-Nonce`、`X-Signature` 签名调用 `/open/*`，时间偏差超过 300 秒或 nonce 重复即拒绝（NFR-04）。实现时需在 `iam_system` 增加应用密钥字段。

=== 6.2 管理与通知扩展

* 授权申请—审批—执行流程（FR-30）。
* 批量导入账号、权限矩阵查询与导出、审计日志导出（FR-06、FR-21、FR-46）。
* 权限变更回调：平台向业务系统 `callback_url` 推送 `{eventId, eventType, affectedUserIds, affectedSystemCodes, occurredAt}`，消费方按 `eventId` 幂等（FR-43）。
* 请求追踪 `X-Request-Id` 回传、写接口幂等键 `Idempotency-Key`。

=== 6.3 安全与限流

* 限流：按用户、IP、调用方系统三个维度，超限返回 429（4001）。
* 防越权：功能权限防垂直越权（已实现）；数据范围防水平越权，"本人"类权限在服务端用当前登录用户回填过滤条件，不信任前端传入的用户 ID（RBAC3）。
* 审计：所有写接口及失败操作写入审计日志，字段见《数据库设计说明书》3.13 节（RBAC3）。
