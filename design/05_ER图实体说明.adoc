== 1. 建模边界

E-R 图只保留以下六个业务实体：

. 多系统
. 前端权限（菜单/按钮树）
. 后端 API
. 角色
. 用户
. 分层组织部门

审计日志和权限变更日志统一为技术支撑表 `iam_log`，不属于本次 RBAC 核心实体模型，因此不在图中出现。令牌、数据范围和角色互斥同样不进入核心 E-R。`iam_user_role` 与 `iam_role_permission` 是表达多对多联系的关系表，不单独画成实体。

== 2. 六个实体

[cols="1,1,3"]
|===
| 实体 | 物理表 | 说明

| 多系统 | `iam_system` | 登记被统一管理的业务系统。前端权限和后端 API 都归属于某个系统。
| 前端权限 | `iam_permission` | 菜单和按钮共用一张自关联树表。`permission_type = MENU/BUTTON`，菜单负责路由与可见性，按钮负责页面操作。
| 后端 API | `iam_api` | HTTP 接口的独立实体，保存 `api_path + http_method`。API 通过 `permission_id` 归于一个前端权限；一个权限可以拥有多个 API。
| 角色 | `iam_role` | 权限集合的业务载体。角色直接获得前端权限，不直接保存 API 路径。
| 用户 | `iam_user` | 登录账号和员工身份，保存所属组织、账号状态及敏感字段密文。
| 分层组织部门 | `iam_org` | 通过 `parent_id` 自关联形成总公司、分公司、部门、项目部层级。
|===

== 3. 联系与基数

[cols="1,1,1,2"]
|===
| 联系 | 基数 | 物理实现 | 语义

| 系统—前端权限 | 1 : N | `iam_permission.system_id` | 一个系统拥有多棵菜单/按钮权限子树。
| 系统—API | 1 : N | `iam_api.system_id` | 一个系统登记多个后端 API。
| 权限—API | 1 : N | `iam_api.permission_id` | 一个菜单/按钮权限可以控制多个 API。
| 角色—权限 | M : N | `iam_role_permission` | 一个角色可授予多个前端权限，一个权限也可授予多个角色。
| 用户—角色 | M : N | `iam_user_role` | 一个用户可拥有多个角色，一个角色可分配给多个用户。
| 组织—用户 | 1 : N | `iam_user.org_id` | 一个组织下有多名用户，一名用户属于一个组织。
| 权限—权限 | 1 : N | `iam_permission.parent_id` | 菜单/按钮树的父子自关联。
|===

== 4. 为什么必须把权限和 API 分开

前端权限回答“页面是否显示、按钮是否可用”，后端 API 回答“这次 HTTP 请求是否允许执行”。如果二者合并为一个功能点，系统只能依赖接口中存在一段路径字段，无法表达一个按钮调用多个接口，也容易把“隐藏按钮”误当成服务端鉴权。

当前模型使用两层校验：

. 前端调用 `GET /open/permissions` 获得用户已授予的权限树节点，渲染菜单和按钮。
. 后端拦截器按 `(api_path, http_method)` 找到 `iam_api`，再读取其 `permission_id`，最后检查用户是否通过角色获得该权限。

因此直接构造 HTTP 请求绕开页面时，后端仍会对 API 做独立鉴权；未登记、未映射权限或未授权的 API 均默认拒绝。

== 5. 与代码边界的对应

[cols="1,1"]
|===
| URL 资源 | Controller / Service

| `/systems` | `SystemController` / `SystemService`
| `/permissions` | `PermissionController` / `PermissionService`
| `/apis` | `ApiController` / `ApiService`
| `/roles` | `RoleController` / `RoleService`
| `/users` | `UserController` / `AccountService`
| `/organizations` | `OrganizationController` / `OrganizationService`
|===

角色的用户分配和权限分配都位于 `/roles` 根资源下，并统一由 `RoleService` 承载，不再拆分 `GrantService`。这样从 URL 能直接定位 Controller，从角色能力能直接定位 Service。
