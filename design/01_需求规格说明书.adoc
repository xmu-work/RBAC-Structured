== 1 引言

=== 1.1 编写目的

本文档面向统一应用软件权限管理系统（以下简称"本系统"或"权限平台"）的需求分析阶段，系统定义业务背景、用户角色、功能需求、非功能需求、对外接口与验收要点，作为后续概要设计、详细设计、编码实现与测试验收的依据。

预期读者：甲方业务代表（信息中心、人力资源部、各分公司综合办公室）、系统分析师与架构师、开发与测试人员、课程指导教师与评审人员、后续运维人员。

=== 1.2 项目背景

a. 本系统为通用统一权限管理平台，面向存在多业务子系统、需集中管控身份与权限的各类企业组织。首个接入案例为某市政公司（约 1 万名员工、1 个总公司 + 9 个分公司），其信息中心为开发与管理单位，人力资源部与安全质量部为业务主管部门。
b. 以首个接入案例为例，该公司现有 18 套在跑业务系统（OA、PMIS、财务、安全生产、合同、成本等），"一人一系统一套权限"，入职、调岗、离职需逐系统手工处理，易漏改、易残留；离职账号清理不及时；部分系统仅靠前端隐藏菜单/按钮，直接调 API 可越权；权限变更生效慢；员工姓名电话明文存储；日志定期删除不满足审计要求。
c. 本系统不重写任何业务系统，而是为各接入企业提供组织级 IAM（身份与访问管理）统一认证与统一授权能力。

=== 1.3 定义

需求用例编号规则：格式为 `IAM-XXX-NNN`，含义如下表。

[cols="1,1,1,3"]
|===
| 前缀 | 文档类型 | 子系统 | 顺序编号
| IAM
| 需求文档
| AUTH：统一认证；ORG：组织账号；ROLE：角色权限；DATA：数据权限；AUDIT：审计日志
| 从 001 开始
|===

术语：

[cols="1,4"]
|===
| 术语 | 定义
| RBAC | 基于角色的访问控制。本系统以 RBAC0 为基础：用户—角色—权限三层绑定。
| 功能权限 | 对"能进哪套软件、哪个菜单、哪个按钮/API、可执行何种操作"的控制，操作取值 12 种（无/查看/全部/查看编辑/查看新增/查看审批/查看导出/查看编辑审批/查看新增编辑/查看编辑导出/查看本人/查看编辑本人）。
| 数据权限 | 对"能看/能操作哪个分公司、部门、项目的数据"的控制，范围：全公司/本分公司/本部门/本项目/本人。
| SSO | 单点登录，一次认证访问有权限的各业务系统。
| 令牌 Token | 本系统签发的身份与权限凭证，业务系统凭其校验。
| 封存 | 离职后保留账号但禁用、解绑角色、不做物理删除、日志保留可查。
| 互斥 | 两角色/两授权在同一用户上不能同时生效（如会计与出纳）。
| 即时生效 | 后端权限变更后前端无需重登录、无需刷新即生效。
|===

== 2 任务概述

=== 2.1 目标

本系统是连接企业全体员工、各接入业务系统与组织架构的统一权限中枢：建立统一账号与统一组织树，以 RBAC 模型统一管理功能权限与数据权限，提供 SSO 单点登录与服务端 API 鉴权，实现权限全生命周期（授予/调岗/回收/离职封存）、前后端双重控制、权限变更即时生效、操作日志永久保存、敏感信息加密脱敏。新增业务系统接入只需登记配置、不改核心代码。

=== 2.2 运行环境

* 操作系统：Linux（CentOS / Ubuntu Server）
* 运行环境：JDK 17+ / Spring Boot 3.x，Nginx
* 数据库：MySQL 8.0；缓存与变更事件：Redis
* 规模：支持万级账号、多套接入系统、数百功能点（首个接入案例：10000 账号、18 套系统、约 359 个功能点）。

=== 2.3 条件与限制

a. 人事主数据（入职/调岗/离职事实）以人力资源管理系统为准，本系统接收事件并执行权限侧处理；人工手动授权/调整仍为本系统职责。
b. 本系统不负责 18 套系统的业务流程与界面聚合，只做认证与鉴权。
c. 员工离职采用封存而非物理删除；日志永久保存、不得定期删除。
d. 敏感信息（姓名、电话）必须加密存储、展示脱敏。

== 3 数据描述

=== 3.1 领域模型

系统核心实体及其关系见配套《ER 图.png》。共 14 个实体，按四组划分：

* 身份与组织：组织机构（iam_org，四级树：总公司/分公司/部门/项目经理部）、账号/员工（iam_user，姓名电话加密、账号状态）。
* RBAC 授权核心：角色（iam_role）、角色互斥（iam_role_exclusion）、用户-角色绑定（iam_user_role，含有效期）、角色-功能授权（iam_role_function，allowed_action）、角色-数据范围授权（iam_role_data_scope）、数据范围字典（iam_data_scope）。
* 业务接入：业务接入系统（iam_system，18 套）、功能模块（iam_module）、功能点（iam_function_point，含 API 路径+方法）。
* 运行与审计：令牌（iam_token，可吊销）、审计日志（iam_audit_log，永久）、权限变更记录（iam_permission_change_log，前后快照）。

== 4 功能需求

=== 4.1 功能划分

参与者与系统边界（用例总图）：

* 外部实体：普通员工（E1）、管理员/审批人（E2）、HR 人力资源系统（E4）、18 套业务系统（E3）。
* 系统内用例包：统一认证与令牌（AUTH）、组织与账号管理（ORG）、角色与功能/数据授权（ROLE/DATA）、变更通知与即时生效、日志审计（AUDIT）。

用例分组：

[cols="2,4"]
|===
| 用例包 | 包含用例
| 统一认证 AUTH | SSO 登录、令牌签发与校验、业务系统鉴权、前端权限查询
| 组织账号 ORG | 组织树维护、账号建立、入职/调岗/离职封存、账号状态管理
| 角色权限 ROLE | 角色定义与继承、角色互斥、角色-功能点授权、批量授予回收
| 数据权限 DATA | 数据范围授权、岗位型数据角色（安全员/预算员/质检员）、临时授权
| 审计日志 AUDIT | 操作日志记录、日志查询导出、变更快照追溯
|===

=== 4.2 功能描述

==== 4.2.1 SSO 登录与令牌签发

[cols="2,2"]
|===
| 用例编号：IAM-AUTH-001
| 用例名称：单点登录与签发令牌
| 级别：子功能
| 参与者：普通员工（E1）、18 套业务系统（E3）
| 描述：用户在任一套业务系统跳转本系统认证，成功后签发带签名、有效期的令牌并回跳。
| 触发事件：用户访问业务系统受保护资源。
| 主成功场景：
a| 1. 用户输入账号密码，系统校验账号状态（正常/停用/封存/锁定）。
2. 校验通过后签发令牌（含用户标识、有效期、签名），写入令牌库。
3. 回跳业务系统并携带令牌。
4. 业务系统凭令牌回调本系统校验，获得该用户功能权限与数据权限。
| 信息：账号密码、令牌、用户标识、权限集合
| 扩展场景：
a| 3a. 账号已封存/锁定：拒绝登录，记录失败日志。
3b. 令牌即将过期：续期；被吊销：业务系统鉴权立即失败。
| 其他：全程记录审计日志（时间、用户、成功与否）。
|===

==== 4.2.2 业务系统 API 鉴权

[cols="2,2"]
|===
| 用例编号：IAM-AUTH-002
| 用例名称：服务端 API 鉴权（前后端双重控制）
| 级别：子功能
| 参与者：18 套业务系统（E3）
| 描述：业务系统后端对每个 API 调用回调本系统校验令牌与权限，不依赖前端隐藏。
| 触发事件：业务请求到达业务系统后端。
| 主成功场景：
a| 1. 业务系统校验令牌有效性、有效期、是否吊销。
2. 本系统返回用户在该系统的功能权限（功能点→操作）与数据范围（分公司/部门/项目/本人）。
3. 业务系统判定：功能点操作权限满足，且目标数据在授权范围内，方可执行。
4. 通过则执行业务；不通过返回无权限。
| 信息：令牌、API 路径+方法、操作权限、数据范围
| 扩展场景：
a| 3a. 前端无权限元素置灰（enable/disable），但后端仍独立校验，绕过前端直调 API 一律拒绝。
| 其他：每次鉴权记录审计日志（成功与否）。
|===

==== 4.2.3 账号与组织管理、离职封存

[cols="2,2"]
|===
| 用例编号：IAM-ORG-001
| 用例名称：账号全生命周期与离职封存
| 级别：子功能
| 参与者：管理员（E2）、HR 系统（E4）
| 描述：建立统一账号，维护四级组织树；入职授权、调岗变更、离职封存。
| 触发事件：HR 入职/调岗/离职事件，或管理员手工操作。
| 主成功场景：
a| 1. 入职：管理员建账号、授初始角色（或接收 HR 事件触发）。
2. 调岗：调整组织归属与岗位，系统列出与新岗位不符的现有权限，人工回收/授予。
3. 离职：账号置"封存"，禁用登录，解绑全部业务角色与数据权限，吊销令牌。
4. 账号与历史日志保留，不做物理删除。
| 信息：账号、组织、岗位、角色绑定、状态
| 扩展场景：
a| 3a. 离职员工尝试登录：拒绝；其历史日志仍可查询。
| 其他：状态变更与封存均记录前后快照与审计日志。
|===

==== 4.2.4 角色与互斥授权

[cols="2,2"]
|===
| 用例编号：IAM-ROLE-001
| 用例名称：角色定义、互斥与功能/数据授权
| 级别：子功能
| 参与者：管理员（E2）
| 描述：维护角色（功能角色/岗位型数据角色），配置角色-功能点授权与角色-数据范围授权，校验互斥。
| 触发事件：管理员配置角色或授权。
| 主成功场景：
a| 1. 定义角色（编码、名称、类型），支持角色继承（禁循环）。
2. 配置角色-功能点（allowed_action 取 12 种之一）与角色-数据范围（全公司/本分公司/本部门/本项目/本人）。
3. 绑定用户-角色；授予时校验互斥（如会计与出纳不能同授）与最小权限。
4. 保存后生成变更事件，权限缓存失效、推送更新，前端即时生效。
| 信息：角色、功能点、操作、数据范围、用户绑定
| 扩展场景：
a| 3a. 互斥冲突：拒绝并提示，操作留痕。
3b. 临时授权：设有效期，到期自动回收。
| 其他：授权/回收全部记录审计日志与变更快照。
|===

==== 4.2.5 岗位型数据权限

[cols="2,2"]
|===
| 用例编号：IAM-DATA-001
| 用例名称：岗位差异化数据范围（安全员/预算员/质检员）
| 级别：子功能
| 参与者：安全员、预算员、质检员等（普通员工 E1）
| 描述：按岗位限定可见数据范围。
| 触发事件：员工访问业务数据。
| 主成功场景：
a| 1. 安全员（约 871 人）仅见本分公司/本项目安全数据，跨项目需专项授权。
2. 预算员（约 820 人）仅见本项目预算，本分公司汇总按授权。
3. 质检员（约 751 人）仅见本项目质检数据，汇总按授权。
4. 功能权限与数据权限联合判定。
| 信息：岗位、组织/项目标识、数据过滤条件
| 其他：数据范围映射组织树节点。
|===

==== 4.2.6 操作审计日志

[cols="2,2"]
|===
| 用例编号：IAM-AUDIT-001
| 用例名称：永久审计日志与查询导出
| 级别：子功能
| 参与者：管理员（E2）
| 描述：记录并留存所有关键操作。
| 触发事件：任何登录、授权、鉴权、封存、导出操作。
| 主成功场景：
a| 1. 记录字段：操作时间、操作内容/动作、用户名、成功与否（扩展：对象、来源 IP、系统）。
2. 日志只追加、不可改、永久保存、不得定期删除。
3. 支持按时间/用户名/操作类型/成功与否查询与 CSV/Excel 导出。
| 信息：时间、动作、用户名、成功与否
| 扩展场景：
a| 1a. 导出明文敏感信息需授权，导出动作本身记录日志。
|===

=== 4.3 业务流程

. 授权流程：申请 → 审批（部门经理/项目经理）→ 校验互斥与最小权限 → 管理员人工授予 → 缓存失效/推送即时生效 → 记录快照与日志。
. 调岗变更流程：HR 事件触发 → 列出现有权限并标记不符项 → 人工回收旧角色/授予新角色 → 互斥校验 → 即时生效留痕。
. 离职封存流程：HR 事件 → 账号封存禁用登录 → 解绑角色/数据权限 → 吊销令牌 → 账号日志保留可查 → 留痕。
. 权限变更即时生效流程：保存变更 → 生成变更事件 → 缓存立即失效/推送 → 前端下次请求获得最新权限，菜单按钮即时刷新，无需重登录。
. API 鉴权决策流程：带令牌请求 → 校验令牌 → 返回身份与权限 → 功能+数据联合判定 → 通过执行/拒绝并记日志。

== 5 性能需求

=== 5.1 数据精确度

* 权限判定结果与组织/角色数据强一致；数据权限按组织树节点与项目 ID 精确过滤，不得串数据。
* 姓名、电话加密存储，展示脱敏规则固定（姓名留姓、电话中间四位掩码）。

=== 5.2 时间特性

* 单次接口鉴权延迟目标：平均 ≤ 100ms，峰值 ≤ 200ms（设计阶段压测为准）。
* 权限变更后前端生效：≤ 推送/缓存失效的一次请求周期（秒级）。
* 支持 10000 账号、18 套系统并发鉴权。

=== 5.3 适应性

* 新增第 19 套系统：登记系统与功能点、映射 API、配置角色权限即可接入，不改核心代码。
* 操作取值集合可扩展，兼容现有 12 种。
* 组织树与角色模型支持后续增加分公司与岗位型数据角色。

== 6 运行需求

=== 6.1 软件接口

本系统向 18 套业务系统提供：

. 令牌校验接口：输入令牌，输出有效性、用户标识、过期时间。
. 权限查询接口：输入用户标识+系统编码，输出功能权限集合与数据范围。
. SSO 认证接口：跳转认证，成功回跳携带令牌。
. 权限变更通知接口：变更时推送失效/更新事件。
. 接入登记接口：登记系统编码、回调地址、密钥。
. 接口调用均记录审计日志（调用方、时间、结果）。

=== 6.2 故障处理

* 本系统作为公司级 IAM 需高可用、避免单点；鉴权服务不可用时业务系统按评审策略短时缓存鉴权结果降级。
* 令牌签名防伪造、防重放；异常调用拒绝并记录。
* 并发/冲突操作加互斥锁，保证授权数据一致与变更快照可追溯。

== 7 其它需求

* 敏感信息加密存储、密钥独立管理、禁止硬编码明文。
* 遵循最小权限：默认无权限，授权方可访问；防水平越权（同角色跨数据）与垂直越权（低权限访问高权限功能）。
* 管理界面易用，权限矩阵可视化，操作有二次确认与明确反馈。
* 日志按容量规划归档，归档后仍可查询导出，不改变"永久保存"属性。
