## 0. 文档定位与事实基准原则

### 0.1 适用范围

- **适用**：权限平台管理后台 Web 端（对应后端 `interfaces/admin/**` 全部接口、登录认证入口、以及 `/open/permissions` 权限下发接口的消费）。
- **不适用**：18 套业务系统自身的前端（它们经 `/open/*` 对接，属各自系统范畴）。

### 0.2 事实基准原则（重要）

后端 RBAC0 已实现（认证、用户、角色、授权、功能权限、开放鉴权接口），只有**角色互斥、数据范围、审计日志 3 块尚未实现**（组织机构的树查询、新建、移动已实现）——其 Controller 签名已定义，但调用返回 500（`INTERNAL_ERROR`），前端这 4 块继续以 mock 开发、不做联调。接口以《API 设计说明书》V2.0 和后端代码为"事实契约"：

1. **设计文档与代码冲突时，以代码为准**，冲突项登记入第 11 章《差异与后端待办清单》，由后端同学限期收敛。
2. 设计文档中有、代码中尚无的能力（SSO、刷新令牌、审批流、导出等），统一标注 **[BACKLOG]**，前端只做预留设计，不先行开发。
3. 标注 **[待后端]** 的条目为联调阻塞项，优先级最高。

### 0.3 契约效力

"必须/禁止"为强制条款，Code Review 逐条检查；"建议"条款允许偏离但需说明理由。

## 3. 数据口径契约（与后端代码对齐后的最终约定）

> 本章全部依据后端实际序列化行为定稿，**推翻了 API 设计文档中的 snake_case 约定**。

| # | 约定 | 依据（代码事实） |
|---|---|---|
| 3.1 | **字段命名：camelCase**。后端 Jackson 默认命名，`Result.requestId`、`PageResult.pageSize`、实体字段（`orgId`、`createdAt`…）均为 camelCase。前端 DTO 与之一致，**禁止**再做 snake/camel 双向转换层 | `Result.java`、`PageResult.java`、各实体类 |
| 3.2 | **ID 为 number**。所有主键/外键为 Long 自增（`userId`、`orgId`、`roleId`…），TS 统一声明 `number`。路由参数可转字符串，但比较/提交必须用 number。例外：登录响应 `LoginResponse.userId` 为 **String**（后端 DTO 如此），登录后前端统一 `Number()` 归一 | 各实体、`LoginResponse.java` |
| 3.3 | **时间双格式**：① 响应中的时间是 **ISO 8601 本地时间**字符串，带 `T`、可能带微秒，不带时区，如 `2026-10-24T16:13:19.170295`（`LocalDateTime` 不受 Jackson `date-format` 影响）；前端展示时**必须**经 `utils/time.ts` 的 `formatDateTime` 转为 `YYYY-MM-DD HH:mm:ss`，禁止直接渲染原串；② 请求中的时间参数（如审计 `startTime`、授权 `expireTime`）发送 **ISO 本地格式** `YYYY-MM-DDTHH:mm:ss`（不带时区，由 `toLocalISO` 产出）。已实测：带空格的 `YYYY-MM-DD HH:mm:ss` 作为请求参数会返回 400 | 后端实际响应、`RoleController.grant` 实测 |
| 3.4 | **空值省略**：`Result` 类标注 `@JsonInclude(NON_NULL)`，`data`/`requestId` 为 null 时**字段整体缺失**，TS 类型一律加 `?`，消费处判空 | `Result.java` |
| 3.5 | **布尔数字化**：`success`、`isDeleted`、`revoked` 等字段后端为 `Integer`（0/1），前端比较用 `=== 1`，禁止当 boolean 使用 | `IamAuditLog.success`、`IamOrg.isDeleted` |
| 3.6 | **version 乐观锁：v1 不传**。现有 Controller 签名均无 `version` 参数；收到 `3008` 统一提示"数据已被他人修改，请刷新后重试"并重新拉取 | 各 Controller 签名 |
| 3.7 | **枚举值全部为大写码**（`NORMAL`、`FUNC`、`HQ`、`VIEW_EDIT`、`ALL`…），全量映射见附录 A。前端字典 store 必须以其为唯一来源，禁止页面内散落中文字面量 | `common/enums/*` |

## 4. API 访问层契约

### 4.1 Base URL 与路径

- 后端 `server.servlet.context-path = /api/v1`，Controller 映射为裸资源路径（`/users`、`/roles/grants`）。**双前缀缺陷已修复**，`vite.config.ts` 中的临时 rewrite 已删除。
- **前端约定**：`axios.baseURL = VITE_API_BASE`，开发环境 `VITE_API_BASE=/api/v1`（经 Vite proxy 到 8080）；资源路径一律写裸路径。

### 4.2 请求形态（与 Controller 签名严格对齐）

| 接口类别 | 传参方式 | 前端封装约定 |
|---|---|---|
| 登录、批量权限判定 | JSON Body（`@RequestBody`） | `data` 传对象 |
| **其余全部写接口** | **`@RequestParam`（query 参数）** | 统一走封装的 `postForm(url, params)`：参数放 URL query，Body 为空。**禁止**自行为其拼 JSON Body（后端不解析） |
| 角色-功能绑定 / 解绑 | 混合：`roleId`（绑定另含 `allowedAction`）走 query，功能点 ID 数组走 JSON Body；解绑是 **DELETE 带请求体** | `system.api.ts` 内单独处理：绑定用 `postJson`，解绑用 `deleteJson`（params + data） |
| 分页/过滤查询 | query：`page`（从 1 起）、`size`（默认 20） | **注意是 `size` 不是设计文档的 `page_size`** |

### 4.3 请求头

| 头 | 约定 |
|---|---|
| `Authorization` | 除 `POST /auth/login` 外所有请求自动携带 `Bearer {accessToken}`（登出/校验接口后端即读此头） |
| `X-Request-Id` | 每请求生成 UUID v4 发送，用于与后端日志关联；**但当前后端不回传 `requestId`**（无 MDC 过滤器，`Result.requestId` 恒 null 被省略），前端不依赖其回显，[待后端] 补过滤器 |
| `Idempotency-Key` | 写请求自动携带 UUID（一次表单会话一个 Key，重试复用）；**当前后端无幂等处理**，该头仅作埋点与语义预留，防重复提交以"按钮 loading 禁用"为实际手段，[待后端] 补幂等拦截 |

### 4.4 统一响应包（按代码定稿）

```json
{ "code": 0, "message": "success", "data": { }, "timestamp": "2026-10-24T16:13:19.170295" }
```

- `code = 0` 且 HTTP 200 → 拦截器解包直接返回 `data`；业务代码只见 data。
- `code ≠ 0` → 进入错误矩阵（4.6）。后端 `GlobalExceptionHandler` 保证 HTTP 状态与错误码匹配（如 3001 → HTTP 409，4001 → 429）。
- 分页数据 `data` 结构：`{ total: number, page: number, pageSize: number, list: T[] }`（`PageResult`，camelCase）。`GET /users` 已返回 `PageResult`；`GET /audit-logs` 尚未实现（RBAC3），实现时同样返回 `PageResult`。前端 `useTable` 只适配 `PageResult` 一种结构。
- `data` 为空时整个字段省略；但 `data` 内部对象的空字段仍输出为 `null`（如 `phoneMasked: null`）。

### 4.5 错误处理矩阵（与 `ErrorCode.java` 逐码对齐）

| code | HTTP | 场景 | 前端统一行为 |
|---|---|---|---|
| 0 | 200 | 成功 | 解包返回 |
| 1001 | 400 | 参数校验失败（缺参数、类型错误、枚举取值非法、业务参数不合法） | toast 后端 `message` 原文。后端未使用 `@Valid`，`message` **不是** `字段: 原因` 格式（缺参数时为 Spring 原始报错），表单页不做字段级回填，必填校验以前端表单规则为准 |
| 1002/1003 | 400 | 缺参/格式错 | toast 原文 |
| 1005 | 404 | 资源不存在（用户、角色、模块、功能点、绑定、未知路径） | toast 原文；详情页可渲染空态 |
| 2001 | 401 | 未登录；**登录接口返回 2001 表示账号或密码错误** | 非登录请求：清会话 → 跳 `/login?redirect=当前地址`；登录请求（`/auth/login`）：不清会话，直接 toast 后端 `message`（"账号或密码错误"） |
| 2002/2004 | 401 | 令牌无效/吊销 | 同上，提示"登录状态失效" |
| 2003 | 401 | 令牌过期 | **v1 无刷新端点**，行为同 2001，提示"登录已过期，请重新登录"（刷新机制见 5.4） |
| 2005 | 403 | 当前登录账号已封存（只在登录时返回） | 强制登出 + 全屏提示（对应 UC-02） |
| 2006 | 403 | 当前登录账号停用/锁定（只在登录时返回） | 强制登出 + 原因提示 |
| 2007/2008 | 403 | 无功能权限/越数据范围 | 操作级 toast；页面级渲染 403 页 |
| 3001 | 409 | 角色互斥冲突（RBAC3，当前不会返回） | 对话框提示冲突角色（UC-05）；`message` 含冲突信息 |
| 3002 | 409 | 角色继承成环 | [BACKLOG]（继承配置端点缺失） |
| 3003 | 409 | 组织移动非法 | 组织树内联提示并还原拖拽 |
| 3004/3005 | 409 | 已封存/重复授权 | toast 原文 |
| 3009 | 409 | 资源已存在（账号、角色编码、系统编码、API 已登记） | toast 原文 |
| 3010 | 409 | 被授权的用户非正常状态 | toast 原文（不登出；2005/2006 只针对当前登录账号） |
| 3006 | 409 | 需审批 | [BACKLOG]（审批流未实现） |
| 3007 | 409 | 临时授权过期 | toast + 刷新授权列表 |
| 3008 | 409 | 并发冲突 | 见 3.6 |
| 4001 | 429 | 限流 | toast"操作过于频繁"，按钮冷却 3s |
| 5000/5001 | 500/503 | 服务器错误 | 全局错误条 + 提示联系管理员 |
| 5002 | 200 | 降级 | 仅 `/open/*` 消费方关心，管理后台不处理 |

**约束**：上述行为全部收口在 Axios 响应拦截器；业务页面默认不写 `try/catch`，仅需自定义展示（如 3001 冲突详情、表单 1001 回填）时局部捕获。

## 5. 认证与会话契约

### 5.1 端点（代码事实：仅三个）

| 端点 | 方法/参数 | 响应 data |
|---|---|---|
| `/auth/login` | POST，JSON：`{ username, password, captchaId?, captchaCode?, clientIp? }` | `{ accessToken, refreshToken: null, tokenType: "Bearer", expiresIn: 7200, userId: string, displayName: string（完整姓名，未脱敏）, accountStatus: "NORMAL" }`；账号或密码错误返回 2001，已封存 2005，停用/锁定 2006 |
| `/auth/logout` | POST，仅 `Authorization` 头，无 Body | null |
| `/auth/validate` | GET，仅 `Authorization` 头 | `boolean` |

### 5.2 会话规则（强制）

1. **存储**：`accessToken`/`refreshToken`/`userId`/`displayName`/`expiresAt`（由 `expiresIn` 换算）只允许经 `tokenStorage` 工具与 auth store 读写，组件禁止直触 `localStorage`。
2. **登录前置**：无 RSA 公钥下发端点（CryptoComponent 是字段级 AES，不用于登录传输），v1 密码经 HTTPS 直传；`LoginForm` 预留 `encrypt` 开关位，[待后端] 补公钥端点后开启，禁止前端硬编码任何密钥。
3. **验证码**：`LoginRequest` 已含 `captchaId/captchaCode`，但无验证码发放端点。登录页预留插槽默认隐藏；连续失败计数逻辑先不做，[待后端] 补 `GET /auth/captcha` 后启用。
4. **状态分支**：`accountStatus ≠ 'NORMAL'` 时不写入会话、不进入系统，按 `DISABLED/SEALED/LOCKED` 给出差异文案。
5. **无感刷新（v1 降级）**：后端无 `/auth/refresh` 端点。v1 策略：令牌有效期 2h（`jwt.access-token-expire=7200`），到期收到 2003 → 引导重新登录。`refreshToken` 仅存档不用。**[待后端]** 补刷新端点后升级为单飞静默刷新（并发请求共享同一刷新 Promise 排队重放）。
6. **登出**：必须先调 `POST /auth/logout` 再清本地；接口失败也照常清本地并跳登录页。
7. **会话恢复**：刷新页面时用 `GET /auth/validate` 校验本地 token，有效则恢复会话；token 无效时拦截器直接返回 401（2002/2004），按错误矩阵清会话。当前后端**无 profile 端点**，用户名/组织等展示数据以登录响应存档为准，[待后端] 补 `GET /auth/profile`。

## 6. 权限控制契约（FR-36~FR-40，按后端现状修订）

### 6.1 权限数据源

- 现状：`GET /open/permissions?userId=&systemCode=ADMIN` 返回**已授权功能点 ID 数组**（`number[]`），需携带 `Authorization` 头。
- `seed.sql` 已在 `iam_system` 登记管理后台自身（`ADMIN`），并登记两类功能点，全部授予超级管理员 `SUPER_ADMIN`（默认账号 `admin / Admin@123`）：
  - **菜单功能点** 10001～10008：与 `constants/permissions.ts` 的 `ADMIN_FUNCTION_POINTS` 一致，用于 L1 路由/菜单；
  - **接口功能点** 20001～20022（20018～20022 为组织接口）：每个对应一个管理端 API（如 20002 = `POST /users`），后端拦截器据此鉴权，前端常量见 `ADMIN_API_FUNCTION_POINTS`。
- 前端约定：
  1. 登录后由 `permission store` 调该接口，权限集合只存于 `permission store`，**禁止**任何组件自行请求或缓存权限数据（FR-38 同源要求）；
  2. **按钮级控制直接用接口功能点 ID**：`v-perm` 的值写触发该按钮的接口对应的功能点（如"新建用户"按钮 `v-perm="ADMIN_API_FUNCTION_POINTS.USER_CREATE"`），前后端判定口径天然一致；
  3. 响应仍**不含操作粒度**（`allowedAction`），`v-perm` 只判定"有无该功能点"。12 种操作取值用于角色-功能绑定配置界面。

### 6.2 三级控制模型

| 层级 | 机制 | 契约 |
|---|---|---|
| L1 路由/菜单 | 静态路由（登录、403、404）+ 动态路由按权限过滤后注册 | 每条业务路由 `meta` 必须声明 `functionPointId: number`；菜单由过滤后的路由表生成，禁止手工维护菜单数据 |
| L2 按钮/元素 | **唯一入口 `v-perm` 指令**，值=功能点 ID（number） | 默认无权限**移除元素**；修饰符 `:disable` 为置灰+悬浮提示。禁止业务组件散落 `v-if` 自行判断权限 |
| L3 接口 | 前端不做安全判断，依赖后端校验 | 前端只把 2007/2008 转译为友好提示。**铁律（对齐 API 说明书 §6.2）：前端控制仅是体验优化，不构成安全边界** |

### 6.3 即时生效（FR-40 / UC-04，v1 降级方案）

后端无 WebSocket（pom 无依赖、无配置类）；后端**不缓存权限**，每个请求实时判定，授权变更后下一次请求立即生效。前端菜单/按钮依赖本地权限集合，v1 采用**双保险轮询**刷新本地集合：

1. **主动失效**：本端用户完成任何授权/回收/状态变更操作后，若操作对象含当前登录人，立即重新拉取权限集合并 diff 更新菜单。
2. **定时轮询**：layout 挂载时每 60s 重拉一次权限集合比对 diff（接口层面即时生效，轮询只决定菜单刷新的延迟，最坏 60s；课程演示场景可接受）。
3. **[BACKLOG]** 后端补 WebSocket/SSE 推送（M10）后，替换为"事件驱动 + 版本号比对"方案，轮询降级为兜底。

**被回收时的交互约定**：当前打开表单的权限被回收时，提交将收到 2007 → 提示"权限已变更"，自动关闭表单并刷新视图；不做无提示拦截。

## 9. UI / 交互统一约束

### 9.1 UI 实现三原则（先于一切组件开发，强制）

1. **布局容器与视觉组件分离**：外层布局容器（`layout/` 主框架、页面壳等）只负责 grid/flex 与间距，**禁止**出现颜色、圆角、阴影、字体等视觉属性；内层视觉组件（卡片、面板、表格壳、菜单、顶栏区块等）才承载颜色/圆角/阴影/字体。效果：调结构只动布局容器，调美观只动视觉组件，两者互不波及。
2. **设计令牌先行，禁止硬编码**：任何组件开发前先产出 `styles/tokens.css`（CSS 变量：颜色、间距、字号、圆角、阴影各一套）；组件样式一律经 `var(--*)` 引用令牌，**禁止硬编码色值与 px**（1px 发丝线等确需例外的场景必须注释说明理由）。Element Plus 主题经 `--el-*` 变量桥接到令牌（`styles/element-theme.css`），全项目只有令牌这一套色板，禁止另建色值体系。
3. **组件粒度 = 单一视觉区块**：每个组件只负责渲染一个独立的视觉区块（侧边栏、顶栏、卡片、表格区各自成组件；禁止把侧边栏与主内容区写进同一个组件）。判定标准：调某个区块的美观只影响那一个文件；若改卡片样式会波及其他区块，说明粒度过粗，必须拆分。

### 9.2 交互统一约束

1. **列表页标准骨架**：查询区（超 3 项可收起）+ 工具栏 + 表格 + 分页；`size` 默认 20；查询需显式触发（回车/按钮）。
2. **二次确认分级**（对齐 NFR-05）：L1 普通=气泡确认（状态启用、一般操作）；L2 高危=对话框+原因必填+后果文案（封存、回收授权、互斥配置、移动组织）。
3. **表单**：前端校验只做体验层，规则与后端 1001 对齐；提交按钮 loading 期间禁用（当前唯一防重手段，见 4.3）。
4. **三态齐备**：所有异步视图必须有 loading / empty / error 三态，禁止白屏。
5. **性能**：用户列表服务端分页（万人规模）；组织树懒加载 + 操作后局部刷新；路由全部懒加载。
6. **时间展示**：后端返回 ISO 本地时间（3.3），一律经 `formatDateTime` 展示为 `YYYY-MM-DD HH:mm:ss`，只做格式化，禁止时区转换。
7. **文案**：错误提示用后端 `message` 原文 + 前端动作建议；枚举文案一律出自 dict store（附录 A）。

## 12. 工程协作契约

- **分支与提交**：`main`（保护）/ `develop` / `feature/*`；Conventional Commits（`feat/fix/refactor/docs/...`）。
- **质量门禁**：ESLint + Prettier + Stylelint + `vue-tsc`，husky + lint-staged 提交即检；CI 卡 `lint + typecheck + build`。
- **Mock 先行**：后端接口未就绪前，按本文档附录 B 的签名造契约级 mock（vite-plugin-mock / MSW），保证契约驱动开发。
- **CR Checklist**：权限是否走 `v-perm`、写请求是否走 `postForm`、枚举是否出自 dict、确认分级是否到位、敏感字段是否误渲染、时间传参是否 ISO 本地格式、样式是否全部引用令牌（无硬编码色值/px）、布局容器与视觉组件是否分离、组件是否只承载单一视觉区块。
- **验收映射（前端负责部分）**：UC-02（封存登录被拒提示）、UC-04（权限回收后轮询内生效免重登）、UC-05（互斥冲突展示）、UC-06（审计查询无删除入口）、UC-07（脱敏展示）。
